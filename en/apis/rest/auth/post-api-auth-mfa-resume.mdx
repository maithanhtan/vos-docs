---
title: 'Resume an account session'
description: 'Obtain a REST API JWT using an existing account session token'
openapi: '/openapi.oms.en.json POST /api/auth/mfa/resume'
---

Send your existing `sessionToken` in the `X-Auth-Session-Token` header, without a request body. Use the account session token returned after authentication.

## Resume the session

Run this Bash example with `curl` and `jq`.

```bash
AUTH_BASE_URL="https://platform.verolabs.co"
COOKIE_JAR="$(mktemp)"
chmod 600 "$COOKIE_JAR"
read -r -s -p "Session token: " SESSION_TOKEN
printf '\n'

AUTH_RESPONSE="$(curl --silent --show-error --fail-with-body \
  --request POST "$AUTH_BASE_URL/api/auth/mfa/resume" \
  --cookie-jar "$COOKIE_JAR" \
  --header "X-Auth-Session-Token: $SESSION_TOKEN")"
unset SESSION_TOKEN

printf '%s\n' "$AUTH_RESPONSE" | jq '{status, methods, expiresAt}'
```

## Handle the response

The response follows the [login flow](/en/apis/rest/auth/post-api-auth-login#login-flow):

- `authenticated`: use `jwt` for REST API requests.
- `mfa_required`: preserve the cookie jar and [verify a second factor](/en/apis/rest/auth/post-api-auth-mfa-verify) using a method in `methods`. No JWT is issued yet.

Continue with step 2 or 3 of the [login procedure](/en/apis/rest/auth/post-api-auth-login#log-in-with-curl), as applicable. Use the same shell and cookie jar. Remove the cookie jar when authentication is complete.

A missing token returns HTTP `401` with `session_missing`. Log in again if the session is invalid. Browser requests must use the `https://platform.verolabs.co` origin.
